# Доска задач

Однопользовательский мини-задачник: три колонки, задачи хранятся в PostgreSQL и меняются только через HTTP API.

Репозиторий: https://github.com/Kostya20292/apree-test-task

## Результат

### Репозиторий и запуск

Нужны Docker, Node.js и pnpm 12.

```bash
pnpm install
cp server/.env.example server/.env
docker compose up -d
pnpm --filter server exec prisma migrate deploy
pnpm dev
```

- Клиент: http://localhost:5173
- API: http://localhost:3000, префикс `/api`
- База из `docker-compose.yml`: PostgreSQL 16, пользователь `tasks`, пароль `tasks`, база `tasks`, порт `5432`

`server/.env` не коммитится. Клиент в разработке проксирует `/api` на порт 3000 и сам в PostgreSQL не ходит.

### Миграции базы

Схема создаётся миграцией Prisma, а не ручным SQL на уже запущенной базе.

- Файл: `server/prisma/migrations/20261015221805_init/migration.sql`
- Таблица `Task`, перечисления `Priority` (`low`, `medium`, `high`) и `Status` (`new`, `in_progress`, `done`)
- Применение: `pnpm --filter server exec prisma migrate deploy`

### Проверки ключевой логики

```bash
pnpm test
```

Команда гоняет сервис задач и HTTP API. Перед каждым HTTP-тестом таблица `Task` очищается. База должна быть запущена, миграции применены. Браузерных e2e нет.

Проверяется:

- создание без названия, описания или с неизвестным приоритетом отклоняется;
- новая задача сохраняется со статусом `new`;
- смена статуса не затирает название, описание и приоритет;
- правка меняет только переданные поля;
- удаление убирает задачу из следующего списка;
- пустая база отдаёт пустой список;
- неизвестный идентификатор отвечает 404, идентификатор не в формате UUID — 400.

### Решения, ограничения и время

Подробности в [docs/decisions.md](docs/decisions.md).

- Одна доска, без входа. Интерфейс на русском.
- Новая задача всегда попадает в колонку «Новая». Внутри колонки порядок по дате создания, новые сверху.
- На ширине компьютера карточку перетаскивают за любую точку. На узкой ширине перенос только кнопками.
- Удаление сразу после подтверждения, без корзины.
- Клиент на Vite, React, TypeScript и MUI. Сервер на NestJS. Данные через Prisma.

Ограничения:

- нет нескольких досок, совместного обновления двух вкладок, сроков, поиска и ручного порядка карточек;
- фильтр живёт только на странице и сбрасывается при перезагрузке;
- на телефоне перетаскивания нет.

На работу ушло около 3 часов.

### Улучшение интерфейса

Дизайн и организация экрана сделаны на своё усмотрение: одна страница, три колонки, диалоги создания, просмотра и удаления.

Небольшое улучшение, которое делает задачник удобнее, — фильтр доски по приоритету: все приоритеты или один выбранный. Реализация была необязательной, фильтр добавлен. Он не пишется в базу. Пустой результат фильтра — отдельная подпись, это не пустая доска.

### Использование ИИ

Для разработки использовал Cursor. Работа шла близко к spec-driven development: сначала зафиксированы требования, решения и план в `docs/requirements.md`, `docs/decisions.md` и `docs/plan.md`, затем по этой спецификации собраны клиент, сервер, миграция и тесты.

Генерация не заменяла проверку. Код сверялся с техническим заданием, прогонялся `pnpm test`, и вручную на широкой и узкой ширине проходился сценарий: создать, открыть, изменить, перенести кнопкой и перетаскиванием, отфильтровать, обновить страницу, удалить.
