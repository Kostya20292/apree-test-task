# Принятые решения

| Тема                       | Решение                                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Пользователи               | Одна общая доска, без входа и ролей                                                                                 |
| Язык интерфейса            | Русский, одна страница и диалоги                                                                                    |
| Приоритет                  | `low` / `medium` / `high`. В интерфейсе: низкий, средний, высокий. По умолчанию — средний                           |
| Новая задача               | Всегда в колонке «Новая»                                                                                            |
| Порядок в колонке          | По дате создания, новые сверху. Ручной порядок не делаем                                                            |
| Перемещение                | На компьютере карточку тянут за любую точку её площади в другую колонку. Кнопки смены колонки остаются для телефона |
| Перетаскивание на телефоне | Не делаем. На узкой ширине перенос только кнопками                                                                  |
| Удаление                   | Сразу после подтверждения в диалоге, без корзины                                                                    |
| Улучшение                  | Фильтр доски по приоритету                                                                                          |
| Фильтр                     | На клиенте, в базу не пишется и после перезагрузки сбрасывается                                                     |
| Клиент                     | Vite, React, TypeScript, MUI                                                                                        |
| Сервер                     | NestJS, REST, валидация DTO                                                                                         |
| Данные                     | Prisma, миграции Prisma, PostgreSQL в Docker Compose. Приложение запускается на хосте                               |
| Идентификатор              | UUID                                                                                                                |
| Ошибки API                 | 400 — валидация, 404 — нет задачи, 500 — сбой. Клиент показывает текст и повтор                                     |
| Обновление карточки        | Перетаскивание показывает новое место сразу и возвращает карточку при ошибке. Остальные действия ждут ответ сервера |
| Тесты                      | Сервис задач и HTTP: создать, изменить, перенести, удалить, пустой список. Браузерных e2e нет                       |
| Структура                  | `client/`, `server/`, `docs/`, `docker-compose.yml`                                                                 |

## Модель данных

`Task`

| Поле        | Тип                              | Правило                                                  |
| ----------- | -------------------------------- | -------------------------------------------------------- |
| id          | UUID                             | первичный ключ                                           |
| title       | строка                           | обязательно, 1–200 символов, пробелы по краям обрезаются |
| description | строка                           | обязательно, 1–5000 символов                             |
| priority    | `low` \| `medium` \| `high`      | обязательно, по умолчанию `medium`                       |
| status      | `new` \| `in_progress` \| `done` | при создании — `new`                                     |
| createdAt   | дата-время                       | ставит сервер, по нему сортируется колонка               |
| updatedAt   | дата-время                       | ставит сервер                                            |

Колонки:

| status      | Подпись  |
| ----------- | -------- |
| new         | Новая    |
| in_progress | В работе |
| done        | Готово   |

## API

Базовый путь: `/api/tasks`.

| Метод  | Путь             | Действие                                                                |
| ------ | ---------------- | ----------------------------------------------------------------------- |
| GET    | `/api/tasks`     | все задачи, в колонке новые сверху                                      |
| GET    | `/api/tasks/:id` | одна задача. 404, если нет                                              |
| POST   | `/api/tasks`     | создать. Тело: title, description, priority. status сервер ставит `new` |
| PATCH  | `/api/tasks/:id` | изменить title, description, priority и/или status                      |
| DELETE | `/api/tasks/:id` | удалить. 404, если нет                                                  |

Фильтр по приоритету на сервер не выносится: клиент скрывает карточки уже загруженного списка.

## Интерфейс

- Одна страница: три колонки.
- Карточка: название и приоритет.
- Диалоги: создание, просмотр/редактирование, подтверждение удаления.
- На карточке кнопки перехода в соседние колонки. Они нужны на телефоне и не начинают перетаскивание.
- На ширине компьютера карточку перетаскивают за любую точку её площади. Отдельной кнопки захвата нет.
- Короткое нажатие без смещения открывает просмотр. Смещение начинает перенос.
- Отпускание в другой колонке отправляет `PATCH` с новым `status`. При ошибке карточка возвращается в прежнюю колонку. Внутри колонки место не меняется: оно по-прежнему определяется датой создания.
- Над доской фильтр: все приоритеты или один выбранный. Пустой результат фильтра — отдельная подпись, это не пустая доска.
- Ширина телефона: колонки друг под другом. Ширина компьютера: колонки в один ряд.
- Состояния: загрузка, ошибка с «повторить», пустая доска с призывом создать задачу.

## Проверки ключевой логики

1. Создание без названия, описания или с неизвестным приоритетом отклоняется.
2. Создание пишет `status = new`.
3. Смена `status` не затирает название, описание и приоритет.
4. Редактирование меняет только переданные поля.
5. Удаление убирает задачу из последующего списка.
6. Пустая база отдаёт пустой список.

## Ограничения для итогового описания

- нет входа и нескольких досок;
- нет совместного обновления экрана у двух открытых вкладок, кроме обычной перезагрузки;
- фильтр не сохраняется после перезагрузки;
- внутри колонки нет ручного порядка: карточки всегда идут по дате создания, новые сверху;
- на телефоне перетаскивания нет, перенос кнопками;
- форма создания, правки и удаления применяется после ответа сервера. Перетаскивание двигает карточку сразу и возвращает её при ошибке.
