# Техническое задание: мини-задачник с канбан-доской

Источник: формулировка тестового задания. Решения, которых в тексте нет, собраны в `decisions.md`.

## Цель

Однопользовательский мини-задачник: канбан из трёх колонок, задачи создаются и меняются через интерфейс, данные хранятся в PostgreSQL и читаются/пишутся только через API.

## Обязательный стек

| Слой   | Технология                                      |
| ------ | ----------------------------------------------- |
| Клиент | TypeScript, React, Material UI                  |
| Сервер | TypeScript, NestJS                              |
| Данные | PostgreSQL                                      |
| Обмен  | HTTP API. Прямой доступ клиента к базе запрещён |

Сборщик фронтенда, ORM, способ запуска базы и набор тестов в задании не заданы.

## Функциональные требования

### Доска

- Три колонки с фиксированными названиями: «Новая», «В работе», «Готово».
- В колонке видны задачи, которые к ней относятся. Внутри колонки они идут по дате создания, новые сверху.
- На компьютере задачу перетаскивают в другую колонку за любую точку площади карточки. Отдельной кнопки захвата нет.
- Пустая доска и пустая колонка имеют явное пустое состояние, а не пустой экран без пояснения.

### Задача

Обязательные поля при создании:

- название;
- описание;
- приоритет.

Обязательные действия:

- просмотр задачи;
- редактирование задачи;
- удаление задачи;
- перемещение задачи между колонками.

После перезагрузки страницы доска показывает те же задачи, в тех же колонках. Данные не хранятся только в памяти браузера.

### Состояния интерфейса

- загрузка данных;
- ошибка загрузки или сохранения, с возможностью понять, что действие не выполнилось;
- пустая доска.

### Адаптив

Интерфейс удобен на ширине компьютера и телефона: колонки, карточки и действия доступны без горизонтальной прокрутки всего экрана на узкой ширине. Точные брейкпоинты в задании не заданы.

## Что нужно сдать

- репозиторий и инструкция запуска;
- миграции базы;
- несколько проверок ключевой логики;
- краткое описание принятых решений, ограничений и потраченного времени;
- одно небольшое улучшение удобства: его нужно предложить. Реализация необязательна;
- если использовался ИИ: где именно он помог и как код проверялся.

## Критерии приёмки

1. Доска показывает три колонки: «Новая», «В работе», «Готово».
2. Задачу можно создать с названием, описанием и приоритетом. Она появляется в колонке новых задач.
3. Задачу можно открыть, изменить и удалить.
4. Задачу можно перенести в другую колонку. После переноса она отображается только там.
5. После перезагрузки страницы задачи и их колонки совпадают с состоянием до сохранения.
6. Клиент не ходит в PostgreSQL напрямую: чтение и запись идут через API.
7. Схема базы создаётся миграциями, а не ручным SQL на уже запущенной базе.
8. Есть проверки ключевой логики, и они запускаются командой из инструкции.
9. На узкой и широкой ширине доской можно пользоваться: создать, открыть, изменить, удалить и перенести задачу.
10. Видны состояния загрузки, ошибки и пустой доски.
